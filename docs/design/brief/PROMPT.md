Design the interface for **EzAssemble**, a web app that turns a wordless flat-pack assembly manual into steps a person can follow from across the room.

I have attached a brief in five parts, the current design tokens, screenshots of the app as it works today, and four real drawings from a manual. Read all of it before designing.

**What I am asking for**

Design the whole application except the inside of the 3D view: the home screen with its drop zone, the waiting screen shown while a manual is read, the step player in all five kinds of step, the finished state, and the problem screens. File 2 lists every screen and state. File 5 lists the artboards and files to hand back.

**The direction**

File 3 sets it: "Read from the floor". The person is two metres away with their hands full, so the step number and the instruction sentence are set at a scale no ordinary web app uses, and everything else stays quiet. Follow that direction. Improve on it where you can, and tell me what you changed and why.

**Three rules that override taste**

1. **Do not design the 3D view's contents.** A teammate owns them. Frame it, size it, and put the playback controls around it. Use the screenshot of the 3D view as the stand-in.
2. **Use the real words in file 4.** No placeholder text anywhere.
3. **Keep every existing token name** in file 5 so the 3D view and the page stay matched. Change values and add tokens freely, and list what changed.

**What good looks like**

- A judge watching on a projector understands the product from the home screen in ten seconds.
- Someone on the floor can read the current instruction in a two-second glance from two metres.
- The waiting screen makes two to three minutes feel like real work being done on *their* manual.
- Nothing on any screen could be mistaken for a dashboard, a landing page template, or IKEA's own brand.

**Start with**

The step player for an ordinary assembly step at 1440 wide (artboard 7), since every other screen takes its type and spacing from it. Show me that one first, with the tokens it uses, before doing the rest.

**The screenshots show what is on each screen, not how it should look.** The current styling is an unstyled placeholder.
